## 观察结果

- 总计 10 次问答，两个来源模式各 5 次；全部页面操作均完成并返回回答或拒答。
- 自动化等待时间（提交到页面显示“回答完成”）：平均 24.3 秒，中位数 14.1 秒。该时间包含浏览器轮询误差，不等同于服务器纯推理延迟。
- 仅课程材料：3 次回答、2 次拒答；平均等待 26.0 秒。
- 课程材料 + 网络补充：3 次回答、2 次拒答；平均等待 22.6 秒。
- 课程材料 + 网络补充模式下，5 次结果中未观察到独立的网络来源区块或网页来源引用。两道预设未覆盖问题都返回了讲义拒答文案；这记录的是页面行为，不推断其配置原因。
- 两种模式均有答案显示讲义页码。此轮只记录页码，不自动点击页码或逐条核查原文，因此不评价引用正确率。
- 跨讲义比较题两种模式都被拒答，说明该措辞和本次检索未得到支持；单次结果不能代表所有跨讲义问题。

## 测试任务

| 类型 | 预设问题 |
|---|---|
| `covered` | 什么是上下文学习（In-Context Learning, ICL）？它和参数更新有什么区别？ |
| `partial` | 课程如何解释 Chain-of-Thought 提示对多步推理的帮助？它的局限是什么？ |
| `uncovered` | 课程有没有给出2025年主流大模型API价格的横向比较？ |
| `cross` | 比较第2讲的提示工程、第3讲的 ReAct Agent 和第4讲的 Harness Engineering，它们分别解决什么问题？ |
| `curated_scenario` | 如果我想快速复习这门课的主线，应当按什么顺序串联四份讲义中的重点？ |

## 限制

- 每个模式和问题组合只运行一次，顺序固定为先仅课程材料、后课程材料 + 网络补充。没有随机化，也没有重复测量。
- 问题由测试任务预先编写。`curated_scenario` 不是参与者自选题，不符合真实用户研究中 own 题的含义。
- 自动化仅确认模式文字、回答完成状态、可见页码及显示的来源区块。没有进行人工事实核查或真实来源辨识测验。
- CSV 的真人评价字段刻意留空；如需真实用户研究，仍须招募参与者并依照 `docs/USER_STUDY.md` 采集。

逐次原始观察和完整回答见 `eval/automated_site_test_results.csv`。
