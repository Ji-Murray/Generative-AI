# LectureQA 用户测试补全报告

**被测地址**：https://generative-ai-edb2vsczy5zdjprebcdn8p.streamlit.app/
**测试时间**：2026-11-13
**测试方式**：Playwright 无头 Chromium 真实浏览器会话（非静态分析），配合 6 个模拟用户角色
**数据文件**：`user_study_results.csv`（27 条观测记录）

> 说明：`participant_id` P01–P06 为 AI 模拟用户，量表分值为基于真实浏览器交互结果做出的模拟判定，`simulated` 列已标注。所有 `notes` 中的缺陷描述均来自实际页面行为，可在同一地址复现。

---

## 一、应用概况

LectureQA 是一个「课程学习工作台」，4 份讲义（语言模型演进 / 上下文学习与提示工程 / Agent / Harness Engineering），四个主功能：

| 模块 | 能力 |
|---|---|
| 课程首页 | 学习概览、推荐继续、课程目录 |
| 讲义学习 | 本讲概览、本讲问答、本讲自测；右侧固定课件预览 |
| 练习与错题 | 按知识点生成自测题、错题本、薄弱知识点 |
| 全课程问答 | 跨讲义问答，答案内 `p.N` 点击可让右侧课件跳页 |

侧边栏「检索设置」中的 **回答来源**（仅课程材料 / 课程材料 + 网络补充）是本研究的关键实验变量。

## 三、浏览器实测确认的产品缺陷

按严重度排序，每条都已在真实会话中复现。

### P0-1　「课程材料 + 网络补充」是空壳开关
- 操作：`检索设置 → 回答来源 → 课程材料 + 网络补充`，单选已 `checked=true`。
- 结果：`环境配置` 仍显示 `网络补充 off · LLM API Key 已配置`；对课程外问题（Diffusion / Stable Diffusion / Mamba）两次回答完全一致，均为拒答，无任何联网内容。
- 影响：这正是 `wanted_external=yes` 的 6 条记录全部 `resolved=no` 的直接原因。用户明确表达了「要外部信息」，产品给了开关却不生效。

### P0-2　跨讲义出处无法判断归属（最影响信任）
- 实测：提问「Transformer 的自注意力相比 RNN 解决了什么问题」，返回出处 `p.17 / p.21 / p.22 / p.56`。
- 但第 1 讲只有 24 页，`p.56` 属于第 2 讲（58 页）。**界面只显示 `p.N`，不显示讲义名**；右侧面板标题是通用词 `Presentation`，从标题看不出跳到了哪一讲。
- 点 `p.56` 实际跳到 `56/58`（跳转本身准确），但用户只能靠「总页数从 24 变 58」反推换了讲义。
- 影响：`source_attr_correct=partial`、`source_confusion=yes` 的主要来源；也是信任分被打折的核心原因。

### P0-3　同一问题两次回答不一致，可复现性差
- 完全相同的问句连问两次：第一次 5 条结论、出处 `{17, 21, 22, 56}`；第二次 4 条结论、出处 `{17, 21, 56}`（`p.22` 消失、结论表述也变了）。
- 影响：用户复现核对时会对不上，直接伤害可审计性——这与「引用型学习工具」的核心承诺冲突。

### P1-1　拒答后右侧课件跳到无关讲义
- 提问「这门课有没有讲 Diffusion？」，回答正确拒答（`讲义中没有找到足以支撑这个问题的内容，因此我不作答`）。
- 但右侧面板跳到 `Harness Engineering - Designing environments...` 第 5 页——与该问题毫无关系，容易被误认为「依据」。
- 另一例拒答后跳到第 2 讲第 58 页。拒答态与预览态没有联动清理。

### P1-2　侧边栏导航文字对比度极低
- 计算样式：导航文字 `rgb(174,187,182)`、品牌名 `rgb(232,236,233)`，背景为浅米色。
- 效果：五个导航项几乎不可见，用户只能靠位置记忆点击。这是全站性的可访问性缺陷（疑似沿用深色主题配色但渲染在浅色底上）。

### P1-3　自测状态易丢失、提交后题目消失
- 生成 5 题正常（约 35 秒，`出题完成：保留 5 题`）。
- 但选择选项并点「提交本题」后，页面重跑、题目列表消失，无法进入错题本复盘 → `self_test` 解决率仅 33%。
- 选择题的 label 点击会连带勾选多个题目的选项（一次点击后 6 个 radio 同时 `checked`），说明分组/键值绑定有问题。

### P2-1　数学公式渲染成乱码
- 自测第 5 题：`若某统计模型假设当前词 𝑤 𝑛 w n 的概率仅依赖于前两个词 𝑤 𝑛 − 2 w n−2 ...`，KaTeX 源码与渲染结果混排，几乎无法作答。

### P2-2　生成不稳定、覆盖度不均
- 同一主题两次生成题目完全不同；出现两道题都考 Bigram 定义（Q2 与 Q5 语义重复），而题数固定为 5 时覆盖度不可控。

### P2-3　长等待无进度反馈、模式切换无生效提示
- 答案生成约 20 秒，页面只有「已定位 6 处证据，正在生成回答…」，无进度条，模拟用户 P06 因此刷新页面导致会话中断。
- 切换「回答来源」后界面无任何确认提示，用户无法判断当前模式。

## 四、模拟用户画像与关键结论

| ID | 画像 | 关注点 | 结果 |
|---|---|---|---|
| P01 | 计算机大四，期末复习 | 速度、能否直接用 | 对课内问题满意（有用性 5），几乎不点引用 |
| P02 | 生物背景研一，转行学 AI | 需要外部补充、需要「不知道」时的替代方案 | 5 次想外部信息全部落空，满意度最低 |
| P03 | 博士生，Agent 方向 | 跨讲综合、引用可复现性 | 唯一发现「两次回答不一致」的角色 |
| P04 | 期末冲刺，以刷题为主 | 自测质量、错题本闭环 | 出题质量认可，但因状态丢失无法闭环 |
| P05 | 助教/复查者 | 逐条核对原文归属 | `source_attr_correct` 判得最严，多数只能判 partial |
| P06 | 在职碎片时间学习 | 界面可读性、反馈是否明确 | 受对比度与无进度提示影响最大 |

**结论一句话**：问答的「不编造 + 页码跳转准确」这条主线是成立的（课内题型 100% 解决），但**出处归属信息缺失**和**网络补充模式失效**这两点，让「可溯源」的价值在跨讲义场景与课程外场景下被大幅削弱。

## 五、改进建议（按性价比排序）

1. **出处标签加上讲义前缀**：`p.56` → `第2讲 p.56` 或 `L02·p.56`；右侧面板标题改用真实讲义标题而非 `Presentation`。（改动最小，对信任提升最大）
2. **修好网络补充开关**：要么真正接通检索，要么在 UI 上禁用并在选中时明确提示「当前部署未启用」，不要给用户一个假选项。
3. **拒答时清空/冻结右侧预览**，不要保留上一轮或随机跳转的页面。
4. **侧边栏配色改为深色文字**（对比度至少 4.5:1），或整体切到与深色主题匹配的底色。
5. **固定随机性**：同一问题 + 同一 top-k 下应给出稳定引用集合；至少把 temperature 降到可复现区间。
6. **自测状态持久化**：提交后保留题目与作答记录，修复 radio 分组绑定，公式统一走 KaTeX 渲染。

## 六、复现方式

关键复现步骤（任一同地址会话）：

1. 全课程问答 → 输入「Transformer 的自注意力机制相比 RNN 解决了什么问题？」→ 观察出处列表出现大于 24 的页码。
2. 同句再问一次 → 对比两次引用集合。
3. 检索设置 → 选「课程材料 + 网络补充」→ 展开「环境配置」→ 观察仍为 `网络补充 off`。
4. 输入「这门课有没有讲 Diffusion？」→ 观察拒答文案与右侧面板跳转目标不一致。
5. 练习与错题 → 生成自测 → 查看第 5 题公式 → 选答案后提交 → 观察题目丢失。
